# liuli 版本迭代记录

> 现行系统规格：`docs/liuli_system_spec.md`。本文件只记录"改了什么、为什么改、影响哪里"，正文规格以 spec 为准。
> MVP 阶段（v7–v48）的演进记录见 `docs/archive/liuli_system_spec_mvp.md` 第 0 节。

## 记录规则

- 新版本追加在最上方，格式：`## x.y.z — YYYY-MM-DD`。
- 版本号规则见 spec 0.1：常规迭代（含小功能、增删列和接口）升修订号，形成里程碑的一批功能升次版本，架构与不兼容重构升主版本；升哪一位由用户决定。
- 每条记录写清：**变更**、**原因**、**影响**（Web / Android / MCP / 数据库）。
- 以功能为主：只展开功能、接口、数据口径、数据库和缺陷修复。纯样式、布局、文案调整一行概括（如"手机组合页布局微调"），不逐项罗列，也不写原因和影响。
- 只有样式调整的版本，整条只写一行变更即可。
- 线上 PostgreSQL 有列变更时，必须写明迁移脚本 `tools/migrations/YYYY-MM-DD_<name>.sql`；只新增表则注明"由 create_all 建表，无迁移脚本"。
- 同一次提交里同步更新 spec 对应章节和顶部"当前版本"。

## 1.0.19 — 2026-10-21

- **变更**：
  - 手机看板组合页在"最近调仓"下方新增"最近建议"：列近 10 天微操报告最近 5 条增持、减持，状态分有效、过期、已执行（建议只对适用交易日当天有效）。
  - 点有效或过期的建议进入"记一笔调仓"，预填组合、标的、方向、股数和现价，理由选"AI 建议"并关联该条；减持股数不少于持仓时记为清仓；已执行置灰不可点。
  - 新增接口 `GET /api/portfolios/adjust-advice/recent`。
  - 修正过时的手机端单元测试：今日报告的来源模块已改为显示中文名，断言同步更新。
- **原因**：看到建议后直接记调仓，少填一遍表单，也让调仓和建议的关联更完整，执行率统计更准。
- **影响**：后端 portfolio 新增只读接口；Android H5 看板组合页、记调仓页；Web、MCP 不变；数据库无变更（状态查询时现算）。

## 1.0.18 — 2026-10-18

- **变更**：
  - 修复组合日盈亏判断"建仓当天"时把无时区的 `created_at` 按 UTC 解读：改为按北京时间解读。
  - 修正 6 个过时的单元测试：文档边界测试改用 1.0.0 重写后的 spec 措辞；Linux 脚本测试改为 H5 `npm run serve`；组合日盈亏测试改按净资产口径断言并固定"今天"，不再依赖运行日期。
  - 调仓建议复核表格分页改用 `defaultPageSize`，与项目分页约定一致。
- **原因**：本地 SQLite 读回的时间不带时区，16:00 以后新建的组合当天日盈亏显示为空；测试长期失败掩盖了真实问题。
- **影响**：后端 portfolio（线上 PostgreSQL 读回自带时区，行为不变）；Web 调仓建议复核；数据库无变更。

## 1.0.17 — 2026-10-17

- **变更**：
  - Web 工作台"操作面板"改为"待办"，与 Android 待办同口径集中处理四类外部输入：推荐词、待导入报告、MCP 笔记、未读预警；列表 + 详情两栏，在详情里直接处理，处理完自动跳到下一条。
  - 右侧运维栏：AI 任务（积压数、上次结果、下次运行、执行中状态与轮询）、异常任务（错误摘要、重跑、跳任务中心）、最近执行；顶部状态条显示待办总数与最早积压、任务异常、今日 AI 调用、最新资讯时间。
  - 新增 `GET /api/console/workbench-operations`，待办页只请求这一个轻量接口，不再借用 `workbench-today`。
  - `workbench-today.todo` 改为四类待办计数（`pending_suggestions / pending_reports / inbox_notes / unread_alerts / total`），与待办页共用一份口径；移除只服务旧操作面板的 `operation_jobs`、`recent_run_requests` 以及 `pending_track_materials / pending_stock_materials / failed_jobs`。
  - 今日看板移除"最近执行记录"卡片（与待办页右栏"最近执行"重复），信息流结构图占满一行；删除旧操作面板组件及其样式。
  - 推荐词通过表单抽为 `SuggestionApproveFields`，AI 推荐词页与工作台待办共用；控制台支持从工作台直接落到任务中心页签。
- **原因**：原操作面板只有计数和三个按钮，报告与笔记两类待办在 Web 上没有入口，任务执行后没有状态反馈，失败任务看不到原因。
- **影响**：Web 工作台、控制台；后端 console、knowledge_base（新增待办计数函数）；Android 无变更；数据库无变更。

## 1.0.16 — 2026-10-17

- **变更**：
  - 修复热度榜趋势一直空白：`GET /api/market-radar/tags/{tag_id}/trend` 新增 `window` 参数，由后端按窗口过滤；此前接口固定返回 7d，前端又按 24h 过滤，结果为空。
  - 热度口径修正：统计时刻改为聚合执行时的当前时间（原为 `max(publish_time)`）；`publish_time` 为空或晚于统计时刻的条目按 `created_at` 计入，不再被所有窗口永久计入。关系图谱共现（`aggregate_edges`）同口径。
  - 趋势接口限跨度并降采样（24h→48 小时、7d→14 天、30d→90 天，最多 200 点），只返回 `stat_time / heat_score / trigger_count / rank_no`。
  - 热度榜按最新快照时刻做进程内缓存，`aggregate_heat` 写入后清空。
  - Web 热度趋势抽屉重做：热度榜与市场热词共用，可切换窗口；去掉前端 EMA 二次平滑；区间变化改为绝对差值。
- **原因**：趋势图空白；空发布时间条目形成永久底噪、未来时间条目会让统计窗口错位；趋势接口不限条数，单标签历史越积越多导致请求和渲染变慢；spec 10.5 不使用百分比变化率。
- **影响**：Web 市场雷达热度榜、市场热词；后端 market_radar；MCP `get_tag_trend` 不变；数据库无变更。

 — 2026-10-15

- **变更**：手机端标的详情、赛道详情每次进入都在后台重新请求，先显示缓存再替换为最新数据。
- **原因**：手机端全局 `refetchOnMount=false`，离开详情不到 5 分钟重进会一直显示旧缓存，评级、估值、趋势报告导入后要等缓存过期或重启 App 才能看到。
- **影响**：Android H5 标的详情、赛道详情；后端和数据库无变更。

## 1.0.14 — 2026-10-15

- **变更**：
  - 笔记与材料并列，经标签归属到标的和赛道：笔记打的标签只要绑定在某个标的或赛道上（`stock_tag_relation` / `track_tag_relation`，status=active），就出现在它的详情里，查询时实时关联，不落中间记录。标的详情和赛道详情返回 `notes` 与 `summary.note_count`。
  - 删除 `stock_research_note` 表及 `GET/POST /api/stock-analysis/stocks/{id}/notes`；Web 标的详情、赛道详情的"笔记"分区直接写知识笔记，默认带上该实体绑定的标签。
  - 材料只剩自动化流程产出：`track_material` 只收 `source_item`，`stock_material` 只收 `source_item` / `company_disclosure`，不再接受 `knowledge_note`。Web 标的事件页去掉"撰写笔记"。
  - MCP `get_stock_profile`、`get_track_detail` 默认 sections 加入 `notes`；赛道详情新增 `notes` 分区。
  - 删除候选赛道连带删除标签时，一并删除这些标签上的笔记标签关联，笔记保留。
  - Android 标的详情、赛道详情的"笔记"分区改用笔记卡片，排在"材料"之前，点开进笔记编辑页。
- **原因**：笔记是用户本人的重大想法，数量少、分量高于材料，不需要确认；原先标的笔记单独存在 `stock_research_note`，笔记页里打了标的标签的笔记在标的详情看不到。另外 `stock_material` 的 `knowledge_note` 类型实际指向 `stock_research_note`，与赛道和规格的含义冲突。
- **影响**：后端 stock_analysis、track_discovery、knowledge_base（新增 `entity_notes.py`）、MCP；Web 标的详情、标的事件页、赛道详情、赛道材料；Android H5 标的详情、赛道详情、材料详情。数据库：
  1. 部署前执行 `tools/migrations/2026-10-15_notes_by_tag_precheck.sql`（只读）和 `tools/migrations/2026-10-15_notes_detach_from_materials.sql`（给赛道材料里的笔记补赛道标签后删除 `knowledge_note` 类型的材料行）；
  2. 部署并重启后执行 `tools/migrations/2026-10-15_drop_stock_research_note.sql`（表非空时中止）。

## 1.0.11 — 2026-10-13

- **变更**：
  - 记调仓支持幂等键 `client_request_id`：手机端每次进确认页生成一个，确认页上重试沿用；同一个值只记一次，重复提交原样返回第一次的调仓（`duplicate = true`）。
  - 清仓改为软删除：持仓行保留，`quantity = 0`、`status = closed`，分组、目标权重、备注不丢；持仓列表和统计排除 closed，再买入时复用该行。
  - 一条微操建议条目（报告里的一个标的）只能被一笔调仓关联，不分批；候选列表隐藏已关联的条目。
  - 调仓提交后更新市值快照失败只记日志，不再让接口报错。
  - 手机端记调仓失败且无明确原因时提示"记录结果未知，可直接重试，不会重复记录"，并刷新看板数据。
  - `tools/ops/purge_portfolio_trades.py` 回滚清仓时按软删除处理。
- **原因**：1.0.10 修复的 500 让同一笔调仓被重复提交 10 次、同一条建议被关联 6 次，清仓还删掉了持仓行上的设置。
- **影响**：后端 `POST /api/portfolios/{id}/trades` 新增可选字段 `client_request_id`、响应新增 `duplicate`；建议候选接口过滤已关联条目；Android H5 记调仓页；Web 不变（Web 按调整后总数现取最新持仓换算增量，重试天然不重复）。
- **数据库**：`portfolio_position_change` 新增列 `client_request_id` 和两个部分唯一索引，迁移脚本 `tools/migrations/2026-10-13_position_change_idempotency.sql`，执行前先跑同名 `_precheck.sql` 确认没有被重复关联的建议。

## 1.0.7 — 2026-10-10

**变更**

- 市场雷达日报输入重构：信息流按编号去重后统一放进 `source_items`，标签下只列 `source_item_ids`，每个标签最多 20 条（重要优先、新的优先）。
- 每个热门标签新增 `heat`：当日命中、此前 7 天日均命中、此前 7 天出现天数；新增 `previous_report`（前一天日报结论）。提示词据此判断新出现 / 突然升温 / 持续热点，以及判断的增强与削弱。

**原因**：同一条新闻命中多个标签时全文重复发送，且原文不设上限；日报要求判断"变化"，但输入只有当天数据。

**影响**：日报内容与提示词文件；Web / Android / MCP 无改动；数据库无变更。

## 1.0.6 — 2026-10-10

**变更**

- 市场雷达日报新增「舆情观察」一节：输入新增 `sentiment_items`（当日全部舆情，重要优先，最多 100 条、正文截至 500 字），热门标签下的信息流带上 `source_type`；仅有舆情时也会生成日报。
- 日报提示词补充舆情使用规则：舆情只作情绪信号，不得单独支撑重大事件、关键变量和「高」级关注建议。

**原因**：舆情此前与新闻混在一起交给 AI，AI 无法区分观点与事实，也没有单独解读。

**影响**：日报内容与提示词文件；Web / Android / MCP 无改动；数据库无变更。

## 1.0.1 — 2026-10-09

**变更**

- 手机 App 支持记调仓：看板 → 组合页新增"＋ 记一笔调仓"和"最近调仓"，记录页 `/portfolio/trade/new`，确认页预览仓位与现金占比变化。

- 数据库：线上执行 `tools/migrations/2026-10-09_drop_position_cost_price.sql`。**必须先部署 1.0.1 并重启，再执行脚本**，否则旧代码读该列会让持仓接口 500。
