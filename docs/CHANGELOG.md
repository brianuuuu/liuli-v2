# liuli 版本迭代记录

> 现行系统规格：`docs/liuli_system_spec.md`。本文件只记录"改了什么、为什么改、影响哪里"，正文规格以 spec 为准。
> MVP 阶段（v7–v48）的演进记录见 `docs/archive/liuli_system_spec_mvp.md` 第 0 节。

## 记录规则

- 新版本追加在最上方，格式：`## x.y.z — YYYY-MM-DD`。
- 版本号规则见 spec 0.1：常规迭代（含小功能、增删列和接口）升修订号，形成里程碑的一批功能升次版本，架构与不兼容重构升主版本；升哪一位由用户决定。
- 每条记录写清：**变更**、**原因**、**影响**（Web / Android / MCP / 数据库）。
- 以功能为主：只展开功能、接口、数据口径、数据库和缺陷修复。纯样式、布局、文案调整一行概括（如"手机组合页布局微调"），不逐项罗列，也不写原因和影响。
- 只有样式调整的版本，整条只写一行变更即可。
- 线上 PostgreSQL 有列变更时，必须写明迁移脚本 `tools/migrations/YYYY-MM-DD_<name>.sql`；只新增表则注明"由 create_all 建表，无迁移脚本"。
- 同一次提交里同步更新 spec 对应章节和顶部"当前版本"。

## 1.0.7 — 2026-10-10

**变更**

- 市场雷达日报输入重构：信息流按编号去重后统一放进 `source_items`，标签下只列 `source_item_ids`，每个标签最多 20 条（重要优先、新的优先）。
- 每个热门标签新增 `heat`：当日命中、此前 7 天日均命中、此前 7 天出现天数；新增 `previous_report`（前一天日报结论）。提示词据此判断新出现 / 突然升温 / 持续热点，以及判断的增强与削弱。

**原因**：同一条新闻命中多个标签时全文重复发送，且原文不设上限；日报要求判断"变化"，但输入只有当天数据。

**影响**：日报内容与提示词文件；Web / Android / MCP 无改动；数据库无变更。

## 1.0.6 — 2026-10-10

**变更**

- 市场雷达日报新增「舆情观察」一节：输入新增 `sentiment_items`（当日全部舆情，重要优先，最多 100 条、正文截至 500 字），热门标签下的信息流带上 `source_type`；仅有舆情时也会生成日报。
- 日报提示词补充舆情使用规则：舆情只作情绪信号，不得单独支撑重大事件、关键变量和「高」级关注建议。

**原因**：舆情此前与新闻混在一起交给 AI，AI 无法区分观点与事实，也没有单独解读。

**影响**：日报内容与提示词文件；Web / Android / MCP 无改动；数据库无变更。

## 1.0.5 — 2026-10-10

**变更**

- MCP 舆情导入 `market_radar.import_sentiment_items` 的 platform 新增「股吧」，与雪球 / 微博 / 知乎同口径入库、去重、参与标签命中与热度；Web 市场雷达来源筛选同步加「股吧」。
- 手机卡片去掉外描边、赛道库卡片改白底，与全站统一。

**原因**：需要接入股吧的散户舆情。

**影响**：MCP 工具说明与校验；Web 来源筛选；Android 无改动（无平台筛选）；数据库无变更。

## 1.0.1 — 2026-10-09

**变更**

- 手机 App 支持记调仓：看板 → 组合页新增"＋ 记一笔调仓"和"最近调仓"，记录页 `/portfolio/trade/new`，确认页预览仓位与现金占比变化。
- 新增增量调仓接口 `POST /api/portfolios/{id}/trades`（买入 / 卖出 / 清仓，只改股数），Web 与手机端共用；整条覆盖的 `POST/PUT /positions` 保留但前端不再使用。
- 现金流水新增 `trade` 类型：调仓默认同步现金，不计入外部资金，不影响日盈亏和复盘收益。
- **修复** Web 新增持仓、调整股数会清空持仓分组、目标权重和备注（改走增量接口）。
- 删除 `portfolio_position.cost_price`：系统只关心资源配置，不关心买入成本，且该列会经 MCP 透出。

**原因**：下单后当场记录，让持仓结构、现金占比和微操建议执行当天就准确。

**影响**

- Android / Web：见上。MCP：`portfolio.get_overview` 不再含 `cost_price`。
- 数据库：线上执行 `tools/migrations/2026-10-09_drop_position_cost_price.sql`。**必须先部署 1.0.1 并重启，再执行脚本**，否则旧代码读该列会让持仓接口 500。
