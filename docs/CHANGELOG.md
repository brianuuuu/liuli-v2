# liuli 版本迭代记录

> 现行系统规格：`docs/liuli_system_spec.md`。本文件只记录"改了什么、为什么改、影响哪里"，正文规格以 spec 为准。
> MVP 阶段（v7–v48）的演进记录见 `docs/archive/liuli_system_spec_mvp.md` 第 0 节。

## 记录规则

- 新版本追加在最上方，格式：`## x.y.z — YYYY-MM-DD`。
- 版本号规则见 spec 0.1：常规迭代（含小功能、增删列和接口）升修订号，形成里程碑的一批功能升次版本，架构与不兼容重构升主版本；升哪一位由用户决定。
- 每条记录写清：**变更**、**原因**、**影响**（Web / Android / MCP / 数据库）。
- 线上 PostgreSQL 有列变更时，必须写明迁移脚本 `tools/migrations/YYYY-MM-DD_<name>.sql`；只新增表则注明"由 create_all 建表，无迁移脚本"。
- 同一次提交里同步更新 spec 对应章节和顶部"当前版本"。

## 1.0.2 — 2026-10-09

**变更**

- 手机 App 看板 → 组合页："＋ 记一笔调仓"按钮从指标区下方移到"最近调仓"卡片下方。
- "组合选择"由卡片内的灰色小字改为卡片标题，与"最近调仓"等卡片标题样式一致。
- "最近调仓"在"全部"视图下，组合名与标的名放在同一行，不再换行。

**原因**：先看最近调仓再决定是否记一笔，操作顺序更顺；组合页各卡片标题统一；单条调仓占一行，列表更紧凑。

**影响**

- Android H5：仅组合页布局与样式。
- Web / MCP / 数据库：无。

## 1.0.1 — 2026-10-09

**变更**

- 手机 App 看板 → 组合页新增"＋ 记一笔调仓"和"最近调仓"（最近 5 条，跟随组合切换）。记录页 `/portfolio/trade/new`：
  - 选组合、标的（优先列持仓，可搜全部 A 股新建仓）、方向（买入 / 卖出 / 清仓）、本次成交股数、理由来源。
  - 选"AI 建议"时可关联同方向的微操建议；同步现金开关默认打开；成交价和日期收在"更多"里。
  - 确认页预览这只标的的仓位占比、现金占比变化和所在分组的目标权重。
- 新增增量调仓接口 `POST /api/portfolios/{id}/trades`：同一事务里读最新持仓、只改股数，其余持仓字段不动；卖出超量、对未持有标的卖出、建议方向与买卖方向不一致时拒绝；清仓删除持仓行；公司行为不估价、不同步现金。
- 现金流水新增 `trade` 类型（调仓同步现金，只由系统生成，金额带符号）。只有入金、出金算外部资金，所以调仓同步现金不影响日盈亏和复盘收益。
- **修复** Web 新增持仓、调整股数会清空持仓分组、目标权重、备注和行情缓存：原先调用整条覆盖的持仓接口，只传了股数。现改走增量调仓接口，表单仍填调整后总数，页面现取最新持仓换算成买入、卖出或清仓。
- Web 持仓表单增加"同步现金"开关（默认打开，公司行为时隐藏且不同步）；"关联微操建议"只列与本次加减方向一致的建议；保存失败时显示后端原因。现金流水列表增加"调仓"类型。
- 整条覆盖的持仓接口（`POST/PUT /positions`）保留，前端不再使用。
- 删除 `portfolio_position.cost_price`：系统只关心资源配置，不关心买入成本。这一列没有任何业务使用，却会经 MCP `portfolio.get_overview` 透出给外部研究员。
- spec 0.1 版本号规则调整为"常规迭代升修订号"。

**原因**：在手机券商下单后当场记录，让持仓结构、现金占比和微操建议的执行匹配当天就准确。调仓不同步现金时，总资产会凭空变化，造成日盈亏失真。

**影响**

- Android H5：新页面和组合页卡片。
- Web：持仓表单改走增量接口，新增同步现金开关和流水类型标签。
- MCP：`portfolio.get_overview` 的持仓不再含 `cost_price`。
- 数据库：线上 PostgreSQL 执行 `tools/migrations/2026-10-09_drop_position_cost_price.sql`（执行前线上 9 行持仓、cost_price 非空 0 行）。**必须先部署 1.0.1 并重启，再执行脚本**：旧代码查询持仓会读这一列，先删列会让所有持仓相关接口 500。本地 SQLite 启动时自动删列，删之前先备份。

## 1.0.0 — 2026-10-08

MVP 阶段结束，发布正式版。

**变更**

- 旧规格 `docs/liuli_system_spec.md`（v7–v48，约 5800 行）归档为 `docs/archive/liuli_system_spec_mvp.md`，冻结不再维护。
- 按当前代码重写 `docs/liuli_system_spec.md`，只描述现状，不再在正文里保留演进过程；版本演进改记在本文件。
- 表结构（54 张）由 SQLAlchemy 模型元数据生成；API 按各模块 `router.py` 整理；任务清单按 `JOB_REGISTRY` 整理。
- 明确线上基线是阿里云 RDS PostgreSQL，SQLite 只是本地开发便利；明确 schema 管理规则（新表 create_all，列变更走 `tools/migrations/*.sql`）。
- README 按 1.0.0 现状重写，详细 API 与表结构不再在 README 重复，统一指向 spec。
- CLAUDE.md / AGENTS.md 删除对不存在的 Web UI 规格文件（`2026-05-16-liuli-web-ui-spec.md`）的约束。

**按代码核实后修正的旧规格描述**

- Android 是"原生薄壳 + 独立手机 H5"，底栏为看板 / 资讯 / 笔记 / 待办 / 我的，不是旧文档里的纯原生"记录 / 新闻 / 报告 / 预警"。
- Web 二级菜单是模块页内页签，不是 `/market-radar/feed` 这类独立子路径；页签名称按 `navigation.tsx` 更新（如"热度榜"、工作台"操作面板"）。
- AI 当前只接入 DeepSeek（`services/deepseek`），不存在 `services/ai/*` 多厂商 client。
- 对外 MCP 已不含 OAuth，只用 `mcp.clients` Bearer Token；`local_only` 字段保留但未生效；MCP 工具已全部上线，不再是"规划中"。
- `lightweight-charts` 已用于标的详情 K 线。
- 预警规则实际生效的只有 `heat` 与 `job_failure`，另有微操风险警示直接生成事件。
- API 汇总补入代码中已有、旧文档缺失的接口（组合全局视图、调仓来源对比、微操建议候选、标的趋势快照、笔记分组排序、研究回流更新删除、AI 按日用量等），删除代码中不存在的 `GET /api/knowledge/research-feedback/{id}`。
- 删除 `job_config` 旧版摊平字段描述、`ai_usage_daily_snapshot` 等未建设设计、MVP 开发顺序等过期内容。

**影响**：仅文档，无代码与数据库变更。
