# 多研究员微操与复盘过滤

## 已确认范围

- 复用研究员、报告、建议和调仓表，不新增表、列、索引或约束。
- 保留 portfolio_001（组合微操大师），新增 portfolio_002（组合趋势进攻师）。
- 新风格围绕已有持仓使用趋势动量和事件催化，具体组合由外部任务指定。
- 外部提前知道研究员编号，沿用 get_researcher_profile，不增加研究员枚举 MCP。
- Web 调仓复盘使用组合、研究员、日期过滤，用户根据过滤结果自行比较。
- 实际调仓按发生日期、建议按适用交易日过滤；收益评估仍可使用该日期范围之后的行情。
- 明细和统计使用同一过滤条件；金额合计覆盖过滤后的所有记录，不受分页影响。
- Web 等待实际调仓和建议两个请求完成后一起更新，切换范围、失败或乱序响应不显示旧合计。
- 报告、大盘判断、调仓明细、关联建议、手机最近建议和新风险预警展示研究员身份。

## 归属与统计

- 上传和导入均检查研究员存在性及 JSON/上传参数的一致性；不接受无身份的新微操报告。
- 同组合、研究员、适用日重导替换旧报告，不同研究员的报告并存。
- 连续个股建议和大盘方向按组合及研究员分别去重。
- execution_status/executed_quantity 对外统一表示明确关联的采纳情况，不再把未关联的同日同向调仓算作采纳。
- 复盘读取实时关联结果，覆盖历史推断缓存的展示值，不在只读查询中修改数据库。
- 明确采纳率分母为筛选范围内已到适用日或已有明确关联的增减持建议，分子为明确采纳或部分采纳的建议。
- 个人判断保留原来源；缺少关联的 AI 来源调仓不能直接认定属于某个 profile。
- 选择单组合只返回该组合口径报告；aggregate_only=true 只返回合计持仓口径，不能与 portfolio_id 同时传入。
- 原始 signal_codes、trend_context 等内容继续保存在 detail_json，新增信号只扩展应用分类。

## 线上 SQL 上线步骤

线上只能执行 SQL，使用 `tools/db/pgsql/20261112_portfolio_researchers.sql`，无需执行 Python 或安装扩展。

1. 部署 `feat-pk-1112` 的接口、页面和 `portfolio_002/profile.md` 文件；SQL 注册的是文件索引，不能替代 profile 文件部署。
2. 在数据库控制台完成备份或快照，记录备份与当前部署版本；SQL 不调用 pg_dump、不建立备份表，也不改变表结构。
3. 在 SQL 文件中将 `cutoff_text` 改成新 profile 启用前的实际截止时点，必须带时区，例如 `2026-11-12T18:00:00+08:00` 仅为格式示例。
4. 保持 `do_apply boolean := false;`，在指向线上业务库的同一连接中执行整份 SQL；此时不修改任何业务表。
5. 导出保存 `result`，核对 database/schema、待补数量、updates 中的变更前记录、conflicts 和 skipped；孤立建议、未导入回流不自动推断身份。
6. 确认备份和预览后，把同一文件中的声明改为 `do_apply boolean := true;`，保持截止时间不变，再整份执行；事务加锁后重新计算计划并检查，冲突即中止。
7. 核对结果为 `mode=applied`，实际更新数与计划数一致，研究员列表含名称正确的 portfolio_002；重复执行应新增0个研究员、补齐0条。
8. 刷新 MCP 工具定义并调用 `get_researcher_profile(researcher="portfolio_002")`，确认能读取完整 profile 后，再配置外部 skill 使用该编码。

脚本以 COMMIT 结束；若控制台报错，执行 `ROLLBACK;` 结束失败事务，不继续单独执行剩余更新语句。

- 截止时点及之后的数据排除；只补历史微操建议和已关联回流的空 researcher_code，已有非空值保留。
- 仅当回流标题符合微操格式、报告关联一致且身份无冲突时才纳入；适用范围包含 active 和 superseded 的历史报告。
- 同组合、研究员、适用日的有效报告若因补齐产生重复，则整笔事务中止。
- 已有 portfolio_002 的名称、路径或状态不符合预期时不覆盖，也不继续补齐。
- 变更前记录导出是审计清单，不替代数据库备份；SQL 不能自行完成文件系统备份。
- 锁等待超时或任一更新失败，整笔事务不提交；不修改个人调仓、建议关联、原始报告文件。
- 本次工作仅在隔离数据库验证，不在生产执行 SQL。

开发环境仍可使用 `tools/dev/backfill_portfolio_researchers.py`：默认预览，`--before` 指定截止时间、`--register-profile portfolio_002` 注册，`--apply` 备份后执行；线上以上述 SQL 为准。

## 验收场景

- 两个 profile 同日同股同向建议分别计样本，各自连续重复仍去重。
- 上传身份冲突在报告文件创建前报错，导入冲突不产生部分记录。
- 同一真实调仓只采纳明确关联的建议；修改或取消关联后查询立即反映新归属。
- profile 与日期过滤同时影响报告、信号、警示、大盘、调仓和金额汇总。
- 过滤后超过一页的调仓，合计仍覆盖所有记录。
- 筛选无数据、快速连续切换和请求失败时，不显示其他筛选范围的旧汇总。
- 新风格信号可导入并显示中文标签；旧 profile 的历史报告仍可正常复盘。
