# 多研究员微操与复盘过滤

## 已确认范围

- 复用研究员、报告、建议和调仓表，不新增表、列、索引或约束。
- 保留 portfolio_001（组合微操大师），新增 portfolio_002（组合趋势进攻师）。
- 新风格围绕已有持仓使用趋势动量和事件催化，具体组合由外部任务指定。
- 外部提前知道研究员编号，沿用 get_researcher_profile，不增加研究员枚举 MCP。
- Web 调仓复盘使用组合、研究员、日期过滤，用户根据过滤结果自行比较。
- 实际调仓按发生日期、建议按适用交易日过滤；收益评估仍可使用该日期范围之后的行情。
- 明细和统计使用同一过滤条件；金额合计覆盖过滤后的所有记录，不受分页影响。
- Web 等待实际调仓和建议两个请求完成后一起更新，切换范围、失败或乱序响应不显示旧合计。
- 报告、大盘判断、调仓明细、关联建议、手机最近建议和新风险预警展示研究员身份。

## 归属与统计

- 上传和导入均检查研究员存在性及 JSON/上传参数的一致性；不接受无身份的新微操报告。
- 同组合、研究员、适用日重导替换旧报告，不同研究员的报告并存。
- 连续个股建议和大盘方向按组合及研究员分别去重。
- execution_status/executed_quantity 对外统一表示明确关联的采纳情况，不再把未关联的同日同向调仓算作采纳。
- 复盘读取实时关联结果，覆盖历史推断缓存的展示值，不在只读查询中修改数据库。
- 明确采纳率分母为筛选范围内已到适用日或已有明确关联的增减持建议，分子为明确采纳或部分采纳的建议。
- 个人判断保留原来源；缺少关联的 AI 来源调仓不能直接认定属于某个 profile。
- 选择单组合只返回该组合口径报告；aggregate_only=true 只返回合计持仓口径，不能与 portfolio_id 同时传入。
- 原始 signal_codes、trend_context 等内容继续保存在 detail_json，新增信号只扩展应用分类。

2026-11-12 通过 liuli MCP get_researcher_profile 确认 portfolio_001 的 ID 为3、名称为组合微操大师。

当时接口返回的25份有效报告都带 portfolio_001；13条调仓中5条 AI 调仓均明确关联其建议，另外8条为个人判断。

## 注册与历史补齐脚本

文件：`tools/dev/backfill_portfolio_researchers.py`。

默认只读预览，支持 PostgreSQL 和 SQLite，不导入应用、不运行建表/迁移、不随启动执行。

连接串通过 `LIULI_DATABASE_URL` 环境变量提供，使用部署环境现有配置，不在命令或文档中写凭据。

先选择新 profile 启用前的明确截止时点，以下仅展示参数格式：

```bash
.venv/bin/python tools/dev/backfill_portfolio_researchers.py \
  --before '2026-11-12T00:00:00+08:00' \
  --register-profile portfolio_002
```

- `--before` 排除此时点及之后的数据，示例时间必须按实际上线安排调整。
- 无需补历史时也可以使用同一命令注册新 profile；已有相同编号、名称和路径则跳过注册。
- 若 portfolio_002 被其他名称或路径占用，停止处理，不覆盖既有研究员。
- 仅补截止前微操报告及已关联回流的空 researcher_code；已有其他研究员编号保持原值。
- 归属冲突、报告关联不一致和补齐后出现多份同日有效报告，会阻止正式执行。
- 孤立建议和未导入回流只列出待核对，不擅自重建关联，也不修改个人调仓或原始报告文件。
- 预览确认无误后，同一命令增加 `--apply` 才执行；不需要本次功能之外的结构迁移。
- 正式执行前自动在 var/db/recovery 保存目标库备份及变更前审计清单；本地 liuli.sqlite3 存在时也做一致性备份。
- PostgreSQL 需要 pg_dump、pg_restore，备份失败即停止；正式修改放在一个事务内，失败回滚。
- 脚本可重复运行，已补齐记录不会重复更新；本次开发没有在生产运行 `--apply`。

上线顺序：部署接口及页面 → 预览脚本 → 注册与按需补齐 → 用 MCP 按 portfolio_002 获取 profile → 配置外部 skill。

## 验收场景

- 两个 profile 同日同股同向建议分别计样本，各自连续重复仍去重。
- 上传身份冲突在报告文件创建前报错，导入冲突不产生部分记录。
- 同一真实调仓只采纳明确关联的建议；修改或取消关联后查询立即反映新归属。
- profile 与日期过滤同时影响报告、信号、警示、大盘、调仓和金额汇总。
- 过滤后超过一页的调仓，合计仍覆盖所有记录。
- 筛选无数据、快速连续切换和请求失败时，不显示其他筛选范围的旧汇总。
- 新风格信号可导入并显示中文标签；旧 profile 的历史报告仍可正常复盘。
