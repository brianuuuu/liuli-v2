# 标的评分报告连续性执行文档

> 版本：1.0.50｜日期：2026-11-07｜状态：已实现并验证，未部署
> 云端基线：`a6169f9f`；原方案提交：`8037caa0`；本轮按用户确认移除新增 MCP 接口与全历史事项汇总。

## 范围与职责

- Skill 负责读取最近三期报告、比较变化、复盘判断及承接未完成事项，保留现有 11 步、数据校验、同业比较和至少三条本次反证检查。
- 后端负责本次引用与评分校验、来源去重、事务保存和页面读取，不维护全历史验证台账。
- 不新增 MCP 工具或权限，不改变已批准的三列及索引，不重算历史评分或调整评分方法。
- 评分规则属于 `stock_analysis`，回流解析属于 `knowledge_base`，报告正文与通用 JSON 提取属于 `basic/report_library`。

## Skill 读取与复盘

- 用现有 `report_library.list_reports` 检索标的报告，再用 `read_report_content` 读取同标的、同研究员最近三个研究日期的有效评分报告。
- 同日修订取最新有效版，研究日期不得晚于本次，不足三期按实际数量分析，正文列明实际阅读范围。
- 列表按创建时间排序，应核对标题日期并按需翻页，不能把 `limit=3` 当作最近三期。
- 默认以上一期为比较对象，另外两期用于观察判断是否反复，每个变化维度和等级都说明理由及依据。
- 同一事项以最新有效结论为准，待验证或证据不足时保留原引用和条件，旧的待验证记录不能重启已完成事项。
- 遇到旧引用、依据缺口或判断冲突时按需追溯更早报告，不承诺恢复全部历史遗漏事项。
- 查询或读取失败须标明缺口，不能当作首次研究；旧报告正文观察点在正文复盘，不补造事项 ID。

## 数据契约

### 存储

| 字段 | 类型 | 用途 |
|---|---|---|
| `report_id` | `INTEGER NULL` | 服务端写入真实来源，并唯一去重 |
| `previous_snapshot_id` | `INTEGER NULL` | 比较报告已入库时，由服务端固定对应快照 |
| `continuity_json` | `TEXT NULL` | 保存比较报告引用和三类连续性内容 |

- 保留唯一索引 `uq_stock_score_snapshot_report_id(report_id)`，允许多条 NULL、同日多版本，不设级联删除。
- 比较报告尚未入库时仍可引用原文，快照基准留空，页面显示报告链接，不自动计算分差或事后换绑。
- 分数、等级、核心逻辑和风险继续使用原字段，连续性不重复保存旧分数、分差或完整原文。

### 报告 JSON

只在原 JSON 顶层追加 `continuity`，比较报告 ID 放在对象内，Skill 不填写快照 ID。

| 字段 | 内容 |
|---|---|
| `previous_report_id` | 比较报告 ID，无可用历史时为 null |
| `change_reasons[]` | `field/type/reason/evidence` |
| `previous_checks[]` | `report_id/check_id/result/reason/evidence` |
| `next_checks[]` | `id/condition` |

- 四个字段均须存在，理由非空，新增事项 ID 和历史引用不得重复。
- `field` 支持六维分、等级、核心逻辑、主要风险和独立总分纠错；`type` 区分新证据、判断修正、数据纠错、方法变化和风险调整。
- `result` 为 `supported/weakened/invalidated/pending/insufficient_evidence`，只有后两类允许空证据。
- Skill 首次提出 1–3 条事项，后续新增 0–3 条，未完成事项沿原 `(report_id, check_id)` 承接。
- 完整字段枚举与示例统一维护在[技能契约](../../../invest_assistant/modules/knowledge_base/external/skills/liuli-stock-rater/references/score-continuity.md)。

## 后端与页面

- 先按真实来源报告查重，已入库报告返回原结果，不因后来的历史变化重新校验或覆盖。
- 只读取本次引用的报告，检查存在性、标的、研究员、研究日期及事项 ID，拒绝自引用或伪造来源。
- 已有快照优先使用保存值，未入库报告从原文读取必要信息，不为建立比较而额外创建历史快照。
- 对历史报告可用的分数和等级核对变化原因，不依赖是否已入库；六维完整且不变时，总分变化仅允许计算纠错或方法变化。
- 保留完整有限评分、正文日期与标题一致、研究员与回流一致等校验，评分不足的报告只保存原文。
- `continuity` 缺失视为旧格式，提供 null、无效对象或废弃快照输入则拒绝，不能静默丢弃新字段。
- 评分追加和回流状态 `parsed` 在同一事务完成，并发只对来源唯一键冲突读取原结果，其他异常正常报错。
- Web 按标的重置评分状态，详情只补最新评分的连续性，单条读取仅处理自身及引用；Web/H5 保留趋势、同日版本、分差和报告入口。

- 保留原 ZIP，新版包为 `invest_assistant/modules/knowledge_base/external/skills/liuli-stock-rater-continuity-1.0.50.zip`。
- 上传保持原文和独立回执，`received` 只表示收到，不能代替评分入库成功。
- 回退前启用 `stock_analysis.score_import_mode=paused` 并停用新技能输出，保留新列和报告，兼容版本须保留新格式拒绝检查。
- `legacy_only` 仅接受旧格式，`active` 恢复正常；禁用该配置也会恢复正常，线上启停仍使用项目根目录标准脚本。

## 验收结果

| 场景 | 结果 |
|---|---|
| 最近三期、旧格式间隔、较早事项 | 按报告引用承接，不执行全历史遗漏拦截 |
| 评分变化与独立总分纠错 | 已入库与未入库来源统一校验，未知历史分数不补零 |
| 比较报告尚未入库 | 保留报告引用，不生成历史快照或自动分差 |
| 后来补录比较报告 | 已保存评分不自动改绑 |
| 错误标的、研究员、未来报告、自引用或无效事项 | 定位拒绝 |
| 同报告重复与并发导入、事务失败 | 返回同一快照或回滚，不产生部分写入 |
| Web/H5 与原评分、页签、报告功能 | 定向检查、类型检查及构建通过 |
