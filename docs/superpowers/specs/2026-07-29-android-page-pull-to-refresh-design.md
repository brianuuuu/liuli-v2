# 安卓内容页下拉刷新与组合页重排设计

## 目标

为安卓 H5 建立可复用的页面级下拉刷新能力。共享组件只负责手势、动画和状态反馈，每个内容页独立决定刷新哪些查询，避免一次下拉影响其他页面。

本次先接入组合看板，同时调整组合页信息顺序并移除标的组合卡片的刷新按钮。

## 组合页布局

组合页从上到下调整为：

1. 四项资产指标：总市值、持仓市值、现金余额、年度盈亏
2. 今日表现
3. 标的组合
4. 标的热力图
5. 组合选择

“标的组合”标题右侧不再显示刷新按钮。组合选择继续使用现有 `portfolioId` 状态和查询键，移动位置不改变切换行为。

## 共享组件

新增 `PullToRefresh` 组件，由内容页按需包裹：

```tsx
<PullToRefresh onRefresh={() => overview.refetch()}>
  <PortfolioDashboardContent />
</PullToRefresh>
```

组件对外只暴露通用能力：

- `onRefresh`: 返回 Promise 的页面级刷新函数
- `children`: 当前内容页
- 可选的禁用状态和无障碍标签

组件不引用 React Query 查询键、API 客户端或具体业务模块。以后资讯、笔记、任务等页面可分别传入自己的刷新函数，或在一个页面刷新多个相关查询。

## 手势与交互

- 仅当当前文档滚动位置位于顶部时允许开始下拉。
- 手势移动达到最小判定距离后锁定方向；只有明显的纵向向下手势进入刷新流程。
- 横向手势仍由现有 `HorizontalTabPager` 处理，不阻止横向看板切换。
- 可滚动控件、按钮、输入框以及带 `data-swipe-ignore` 的区域不启动下拉刷新。
- 拖动采用阻尼，触发阈值为 `64px`，视觉位移最多为 `88px`。
- 未达到阈值时松手直接回弹；达到阈值后显示“释放刷新”，松手执行刷新。
- 刷新期间显示“正在刷新”，锁定重复触发，完成后回弹。
- 刷新失败时保留已有内容，短暂显示“刷新失败，请重试”，不替换整页。
- 顶部状态层覆盖在内容上方，不永久占据空间，不改变卡片布局。

状态文案通过 `aria-live` 对辅助技术可见。

## 数据流

组合页下拉时只调用当前 `portfolioId` 对应的 `overview.refetch()`。不增加新接口、不清除全局缓存，也不刷新今日、市场、赛道或标的看板。

切换组合仍通过现有查询键 `["portfolio-overview", portfolioId]` 获取数据。刷新期间保留当前组合内容，避免页面闪空。

## 样式

- 刷新指示器使用现有主题变量和克制的旋转图标，不增加阴影或渐变。
- 内容整体随下拉产生轻微位移并平滑回弹。
- 支持浅色、深色和跟随系统主题。
- 保持 320px、360px、407px 和 412px 视口无横向溢出。

## 测试

- 共享组件测试覆盖：顶部纵向下拉触发、未过阈值不触发、横向手势不触发、非顶部不触发、刷新期间禁止重复触发、失败状态回弹。
- 组合页测试验证 DOM 顺序为“四项指标 → 今日表现 → 标的组合 → 标的热力图 → 组合选择”。
- 验证旧刷新按钮消失，下拉仅调用当前组合概览的现有请求。
- 验证组合切换、空数据、加载和错误状态保持原有行为。
- 运行安卓 H5 全量测试、TypeScript 检查、生产构建和 `git diff --check`。
- 在 320px、360px、407px、412px 及明暗主题下进行真实浏览器检查。

## 非目标

- 本次不为其他内容页立即接入下拉刷新。
- 不修改后端接口、数据库、缓存协议或组合计算逻辑。
- 不实现全局下拉刷新、页面自动刷新或吸顶刷新按钮。
