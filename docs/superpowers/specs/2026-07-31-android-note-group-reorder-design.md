# 安卓笔记分组长按排序设计

## 目标

在安卓 H5“编辑分组”弹层中支持长按拖动自定义分组，并通过原子后端接口持久化顺序。“全部”固定在笔记分类第一位，不参与排序。

## 交互设计

有效自定义分组继续按 `sort_order`、`id` 排列。每行增加拖动手柄，同时允许在不属于按钮的行区域长按：

- 按住约 `350ms` 后进入拖动状态。
- 激活前保留普通纵向滚动，移动超过手势容差则取消长按。
- 激活后当前行跟随手指纵向移动，相邻分组根据行中心交叉位置换位。
- 列表超出弹层高度时，靠近顶部或底部自动滚动。
- 松手后立即显示新顺序并开始保存。
- 拖动使用边框、背景色、拖动手柄状态和占位线反馈，不增加突兀阴影或渐变。

“移除”按钮、关闭按钮和新增分组输入区不会启动拖动。排序区域增加 `data-swipe-ignore`，防止触发页面横滑；拖动激活后阻止列表纵向滚动抢占。

## 固定分组

“全部”由前端固定生成并始终位于第一位：

- 不出现在可拖动列表中。
- 不包含在排序请求中。
- 不写入数据库 `sort_order`。

当前选中的自定义分组只改变显示位置，不因排序切换选中状态。

## 原子排序接口

新增接口：

```http
PUT /api/knowledge/note-groups/reorder
Content-Type: application/json

{
  "ordered_ids": [3, 1, 5]
}
```

后端规则：

- `ordered_ids` 不允许重复。
- 所有 ID 必须存在且状态为 `active`。
- 请求必须完整包含当前全部有效自定义分组，避免遗漏导致顺序不确定。
- 在一个数据库事务中依次写入连续 `sort_order`，从 `0` 开始。
- 成功返回按新顺序排列的有效分组列表。
- 校验失败返回 `400`，不存在的分组返回 `404`，不写入任何部分结果。

现有单分组创建、更新和归档接口保持不变。

## 前端状态与错误处理

- 拖动松手后先乐观更新弹层列表和顶部分类顺序。
- 保存成功后用接口返回列表更新 `note-groups` 查询缓存，再触发后台校验。
- 保存失败时恢复拖动前顺序，显示“排序保存失败，请重试”。
- 保存期间禁止再次拖动和移除分组，避免并发顺序覆盖。
- 新建分组继续使用现有接口，但 Android 传入当前最大 `sort_order + 1`，使新分组默认追加到末尾；刷新后仍按后端 `sort_order / id` 进入列表。

## 测试

后端测试覆盖：

- 完整有效 ID 列表按请求顺序写入连续 `sort_order`。
- 重复 ID、缺失有效分组、归档分组和不存在 ID 均拒绝且不部分写入。
- 列表接口按新顺序返回。

Android 测试覆盖：

- 按住未达到门槛不会拖动。
- 普通纵向滚动会取消待激活长按。
- 长按后可向上、向下换位并发送完整 ID 顺序。
- 拖动区域隔离横向分页手势。
- 保存期间禁止并发操作。
- 保存失败恢复旧顺序并提示。
- “全部”固定第一位且不进入请求。
- 新建分组默认追加到自定义分组末尾。

## 非目标

- 不支持跨账号或跨设备的实时协同排序。
- 不修改笔记内容排序。
- 不让“全部”参与排序。
- 不修改 Web 分组管理界面，但新增后端接口可供未来复用。
