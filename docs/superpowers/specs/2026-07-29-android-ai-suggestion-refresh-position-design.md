# 安卓 AI 推荐词审核返回刷新与位置恢复设计

## 目标

在安卓 H5 的“AI 推荐词”页面审核通过单个推荐词后，返回待审核列表时立即移除该词、重新校验服务器数据，并尽量保持用户进入详情前的阅读位置。

本次只增强单条“通过”流程。单条拒绝、一键拒绝、审核表单和后端接口保持现状。

## 交互流程

用户点击待审核推荐词进入详情前，列表记录：

- 当前文档滚动高度，作为位置恢复兜底。
- 当前词条的下一条已加载推荐词 ID，作为返回锚点。
- 锚点元素相对视口顶部的偏移量，用于恢复其原有视觉位置。

审核通过成功后：

1. 从所有 `["ai-tag-suggestions"]` 前缀的无限查询缓存中移除已通过词条，并同步修正页内总数。
2. 清理该词条的详情会话缓存。
3. 返回 `/tasks` 的 AI 推荐词页。
4. 列表完成渲染后，优先把锚点词条恢复到进入详情前的视口偏移；锚点已不存在时恢复记录的滚动高度。
5. 后台重新拉取待审核列表，校验最新服务器状态。

返回过程不清空整份无限列表缓存，因此已加载页、列表内容和滚动上下文不会先变为空白。

## 状态保存

列表返回状态使用路由 `location.state` 传递，不创建长期持久化数据。状态包含：

```ts
type AiSuggestionReturnState = {
  scrollY: number;
  anchorId?: number;
  anchorOffset?: number;
};
```

详情页在审核通过后把该状态带回 `/tasks`。列表恢复完成后使用替换导航清理一次性状态，避免用户后续重新进入任务页时重复跳动。

推荐词卡片增加稳定的 `data-suggestion-id` 标识，仅供恢复定位和测试使用，不改变样式或业务接口。

## 缓存与刷新

缓存更新保持现有查询键 `["ai-tag-suggestions", "pending"]`：

- 通过成功后使用 React Query 的缓存更新能力移除对应 ID。
- 每页保留原有 `offset`、`limit` 和 `has_more`；`total` 最低减至零。
- 返回后触发待审核查询重新获取，避免只依赖乐观缓存。
- 后台刷新期间继续展示缓存列表，不增加整页加载闪烁。
- 刷新失败时保留已更新的本地列表，用户仍可继续审核；后续进入页面或手动操作会再次校验。

不修改 `mobileApi`、后端审核接口、数据库、排序或分页协议。

## 位置恢复

位置恢复优先级：

1. 找到记录的下一条推荐词锚点时，计算其当前位置与原偏移量的差值并滚动修正。
2. 找不到锚点时，恢复进入详情前的 `scrollY`。
3. 页面内容不足以到达原位置时，由浏览器自然限制到最大可滚动高度。

恢复安排在推荐词列表渲染完成后的动画帧执行，避免路由刚切换时元素尚未挂载。该行为只作用于从推荐词审核详情返回的场景，不改变任务页标签切换已有的滚动记忆。

## 测试

- 验证点击词条时把滚动高度、下一条锚点 ID 和视口偏移传入详情页。
- 验证单条审核通过后从已加载缓存移除当前词条、修正总数并发起新的待审核请求。
- 验证返回列表后优先按锚点恢复位置。
- 验证锚点缺失时按原滚动高度兜底。
- 验证后台刷新时列表不会清空或跳回顶部。
- 验证单条拒绝流程保持原有行为，不应用新增的通过后位置恢复逻辑。
- 运行安卓 H5 相关测试、TypeScript 检查、生产构建和 `git diff --check`，不运行数据库测试。

## 非目标

- 不为其他详情页增加通用滚动恢复框架。
- 不改变横向任务分页器的标签滚动记忆。
- 不修改批量拒绝流程。
- 不增加固定按钮、动画提示或新的审核交互。
