# 1.0.1 手机端调仓记录 设计

> 状态：已实现（2026-10-09）
> 版本：1.0.1
> 影响面：后端 portfolio、手机 H5、桌面 Web（调仓表单与现金流水）、数据库（删列，视线上数据而定）、spec / CHANGELOG / Android 规格

## 1. 背景与目标

在手机券商 App 下单成交后，直接在琉璃 App 上把这次调仓记下来，让持仓结构、现金占比和微操建议的执行情况当天就是准的。

系统关心的是**资源配置是否合理**，不关心持仓的买入成本。所以这次功能的重点是记下"数量变了多少、为什么变"，并让你在提交前看到配置的变化；成交价只是辅助信息。

不做：成本价、浮盈浮亏、手续费税费、成交流水、在手机上编辑分组和目标权重、在手机上做现金校准、撤销调仓。

## 2. 入口与页面

### 2.1 入口

看板 → 组合页，在指标区（总市值 / 持仓 / 现金 / 月度盈亏）下方放一个"＋ 记一笔调仓"按钮。

- 当前选中单个组合时，表单直接带入这个组合。
- 当前选"全部"时，表单的组合项为必选，默认上次用过的组合（存在 localStorage）。

第一版只有这一个入口。表单是独立路由，以后从待办等地方增加入口时直接复用。

### 2.2 记录页 `/portfolio/trade/new`

全屏详情页，隐藏底栏，顶部有返回按钮。路由参数：`?portfolio_id=`。

| 字段 | 规则 |
|---|---|
| 组合 | 单选。从单组合视图进入时固定 |
| 标的 | 搜索框。为空时列出当前组合的持仓（名称、股数、占比）；输入后搜全部 A 股（`/api/stocks/search`），选中不在持仓里的股票即为新建仓 |
| 方向 | 买入 / 卖出 / 清仓。新建仓只能选买入；清仓时股数自动等于现有持仓且不能改 |
| 股数 | 本次成交股数，必须为正数。卖出不能超过现有持仓 |
| 理由来源 | AI 建议 / 个人判断 / 资金调配 / 其他，选填。不提供"公司行为" |
| 关联建议 | 选"AI 建议"后显示，数据来自 `/api/portfolios/adjust-advice/candidates`，只列与方向一致的建议（买入对应增持，卖出和清仓对应减持）；可以不关联 |
| 同步现金 | 开关，默认打开。打开时按"股数 × 成交价"增减现金 |
| 备注 | 选填 |
| 更多（折叠） | **成交价**：选填，占位文字显示持仓现价，留空由系统估算；**日期**：默认今天，可改为更早的日期补录，不能选未来日期 |

### 2.3 确认页

点"下一步"后在同一路由内切换到确认视图，不另开路由：

```text
实盘A · 宁德时代
股数      1,000 → 1,500（+500）
仓位占比  12.4% → 18.6%     分组：卫星仓 目标 20%
现金占比  25.0% → 18.8%     同步现金 −6,150
理由      AI 建议（10-08 增持）
日期      2026-10-08 · 成交价 12.30（留空时显示"系统估算"）
[ 返回修改 ]  [ 确认记录 ]
```

占比在前端按组合当前数据估算：

- 组合当前数据取自 `/api/portfolios/{id}/dashboard`，每次进入记录页都重新请求，不用看板的 5 分钟缓存。
- 估算用的价格：填了成交价就用成交价，否则用持仓现价；新建仓且没有现价时，占比显示"--"。
- 同步现金时总资产不变；不同步时总资产按增减额变化。

最终数字以服务端结果为准，确认页只做提示。

### 2.4 提交后

- 返回组合页，提示"已记录"。
- 让 `portfolio-overview` 和新增的 `portfolio-trades` 查询缓存失效。

### 2.5 组合页"最近调仓"

在"标的热力图"之后、"组合选择"之前新增一个卡片，显示最近 5 条调仓，跟随组合选择切换："全部"时跨组合显示，并在每条上标出组合名。

每条显示：日期、标的、`+500 股` / `−300 股` / `清仓`、理由来源。

数据来自 `/api/portfolios/position-changes?limit=5` 或 `/api/portfolios/{id}/position-changes?limit=5`。只展示不能点，第一版不做详情页。

## 3. 后端

### 3.1 新接口 `POST /api/portfolios/{portfolio_id}/trades`

现有的新增和修改持仓接口是"整条持仓覆盖"，只改股数也必须回传所有字段，而且如果手机端缓存里的持仓数已经过时，算出来的调整后总数就是错的。因此新增一个按增量记账的接口：

```json
{
  "stock_id": 1,
  "side": "buy | sell | close",
  "quantity": 500,
  "price": 12.30,
  "trade_date": "2026-10-08",
  "reason_type": "ai_advice | personal | fund_allocation | other | null",
  "advice_item_id": 88,
  "sync_cash": true,
  "note": ""
}
```

服务端在**同一个事务**里完成：

1. 读最新持仓。`buy` 时持仓不存在就新建，只设置 `stock_id`、`quantity`、`status=active`，其余字段为空。`sell` 或 `close` 时持仓不存在，返回 400。
2. 计算调整后股数。`sell` 超过现有股数返回 400；`close` 忽略传入的 `quantity`，直接归零。
3. 只更新 `quantity`，持仓的其他字段一律不动。`close` 时删除这条持仓。
4. 调用现有的 `record_position_change` 写调仓记录。价格估算、建议关联校验、执行情况重算的口径和 Web 完全一致。建议的方向必须和 `side` 一致，否则返回 400。
5. `sync_cash=true` 且价格（手填或估算）不为空时，写一条现金流水（类型 `trade`，金额带符号：买入为负、卖出为正），同步更新现金余额；流水备注自动生成为"调仓 宁德时代 +500 股"。价格为空时不同步现金，并在返回里告知。
6. 返回 `{ change, position_quantity_before, position_quantity_after, cash_flow, cash_synced }`。

校验：`quantity > 0`（`close` 除外）；`trade_date` 不能晚于今天；`reason_type` 不接受 `corporate_action`（公司行为只能在 Web 上记）。

### 3.2 现金流水类型 `trade`

- `PortfolioCashFlow.flow_type` 新增 `trade`，只由系统生成。手动新增现金流水的接口仍然只接受原来五种类型，不接受 `trade`。
- 现金余额更新：`trade` 按带符号金额直接加到余额上。
- 日盈亏和复盘收益只把入金、出金当作外部资金，`trade` 不计入，所以调仓不会制造假盈亏。

### 3.3 Web 调仓同步加开关

Web 新增和修改持仓表单的"调仓信息"区域加一个"同步现金"开关，默认打开；理由选"公司行为"时强制关闭并隐藏。

后端在 `PortfolioPositionCreate` 上增加 `change_sync_cash: bool = False`。默认值为 False，是为了让没传这个字段的旧调用方行为不变；Web 显式传 true。删除持仓不同步现金。

现金流水列表的类型标签增加"调仓"。

## 4. 删除 `cost_price`

系统不关心买入成本，这一列也没有任何业务使用：没有计算、没有页面展示、评估和复盘都不用。但它会通过 MCP `portfolio.get_overview` 输出给外部 AI，容易误导研究员。

**前提**：先在线上执行只读查询 `SELECT count(*), count(cost_price) FROM portfolio_position;`。如果 `count(cost_price) > 0`，先由用户决定是否导出留档。

改动：

- 迁移脚本 `tools/migrations/2026-10-XX_drop_position_cost_price.sql`：`ALTER TABLE portfolio_position DROP COLUMN IF EXISTS cost_price;`
- `models.py` 删除这一列和本地老库"改为可空"的升级分支；`schemas.py`、`_position_dict`、Web `types/api.ts` 删除这个字段。
- 两个测试相应修改。
- 本地 SQLite 老库多出的这一列，ORM 不读不写，不影响运行，不额外处理。

## 6. 测试

只写不清空数据库的单元测试和接口测试，运行前按项目约束确认目标数据库并备份。

- trades 接口：
  - 买入新建仓、加仓、卖出、清仓删除持仓
  - 卖出超量、对不存在的持仓卖出时拒绝
  - 持仓的其他字段不被改动
  - 现金同步的符号和余额正确；价格为空时不同步
  - 关联建议的方向不一致时拒绝
  - `trade` 流水不进入外部资金统计
- 手动新增现金流水时拒绝 `trade` 类型。
- H5：
  - 表单校验（超量、清仓锁定股数、新建仓只能买入）
  - 确认页占比估算
  - 提交成功后缓存失效

## 7. 结论与实现差异

- 线上查询：9 行持仓，`cost_price` 非空 0 行，直接删列，迁移脚本 `tools/migrations/2026-10-09_drop_position_cost_price.sql`。
- 本地 SQLite 老库的 `cost_price` 可能仍是 NOT NULL，模型去掉后会导致插入失败，因此 `ensure_portfolio_schema` 改为启动时删列（先备份），而不是留着不管。
- 3.3 改为：Web 新增和调整持仓也改走 trades 接口（修复原先整条覆盖会清空分组、目标权重、备注和行情缓存的问题），表单仍填调整后总数，由页面现取最新持仓换算成增量；trades 接口因此接受公司行为（不估价、不同步现金），手机端仍不提供。整条覆盖接口不再加 change_sync_cash。
- H5 没有全局提示组件，提交成功后直接回到组合页，"最近调仓"里出现的新记录即为确认，不另做"已记录"提示。
