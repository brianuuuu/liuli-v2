# 安卓资讯模块下拉刷新设计

## 目标

移除资讯列表顶部的数量和刷新按钮工具行，为每个资讯分类接入页面级下拉刷新，并保持分类横滑、分页加载和详情导航不变。

## 页面结构

资讯根页继续包含四个横向分类：

- 全部
- 重要
- 公告
- 个股

每个分类内容从顶部直接展示加载状态、错误状态、空状态或时间线列表，不再渲染 `timeline-toolbar`，也不保留原工具行高度。

## 下拉刷新

每个 `NewsTimeline` 独立使用现有 `PullToRefresh` 组件：

- 仅在文档滚动到顶部时响应纵向下拉。
- 只调用当前分类对应无限查询的 `refetch()`。
- React Query 重新获取第一页并重建当前分类的分页数据，已经加载的旧后续页不会与新第一页混合。
- 刷新期间保留当前列表，避免内容闪空。
- 刷新失败时保留旧内容，由公共组件短暂显示失败提示。
- 当前分类刷新不失效或请求其他资讯分类。

下拉刷新继续遵循共享组件的方向锁定和交互目标排除规则，不修改 `HorizontalTabPager`。分类横滑、资讯点击和底部加载更多仍按现有逻辑工作。

## 无障碍与手势

- 每个分类使用包含分类名称的下拉刷新无障碍标签，例如“全部资讯下拉刷新”。
- 资讯卡片点击区域保持可访问。
- 下拉刷新不会从底部导航、按钮或其他交互控件开始。

## 测试

- 验证资讯数量和刷新按钮整行消失。
- 验证在“全部”分类下拉只增加“全部”请求。
- 验证切换到“公告”后下拉只增加“公告”请求。
- 验证刷新期间保留旧列表。
- 验证刷新成功后分页从新第一页重新开始，并能继续加载下一页。
- 验证刷新失败保留内容，横向切换和点击详情不回归。

## 非目标

- 不修改资讯后端接口、筛选参数或分页协议。
- 不给资讯列表增加数量统计的新位置。
- 不增加自动刷新、固定刷新按钮或全局下拉刷新。
- 不修改 Web 资讯页面。
